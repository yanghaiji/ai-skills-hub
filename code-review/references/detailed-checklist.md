# 详细审查检查清单

深度审查时逐条对照的检查项，按五大维度组织。常规审查无需使用本文件，大型变更、安全敏感模块、核心业务逻辑审查时加载。

---

## 一、正确性检查清单

### 1.1 逻辑正确性

- [ ] 条件判断是否覆盖所有分支（if/else/switch）
- [ ] 循环是否有正确的终止条件
- [ ] 递归是否有终止条件和防溢出保护
- [ ] 运算符优先级是否正确（特别注意 `&&`/`||` 混用）
- [ ] 整数运算是否考虑溢出
- [ ] 浮点数比较是否使用精度范围（`Math.abs(a - b) < epsilon`）
- [ ] 类型转换是否安全（窄化转换、拆箱 NPE）

### 1.2 边界与异常

- [ ] 空集合/空数组是否处理
- [ ] null 值是否处理（入参、返回值、数据库查询结果）
- [ ] 字符串为空/空白是否处理
- [ ] 除零风险是否排除
- [ ] 数组/列表越界是否防护
- [ ] 大数值/溢出场景是否处理
- [ ] 异常是否被正确捕获和处理（不吞异常、不空 catch）

### 1.3 并发安全

- [ ] 共享可变状态是否有同步保护
- [ ] 双重检查锁定是否使用 volatile
- [ ] 非线程安全类（HashMap/SimpleDateFormat）是否在并发场景误用
- [ ] 事务边界是否正确（传播行为、隔离级别）
- [ ] 分布式场景是否考虑幂等性
- [ ] 乐观锁/悲观锁选择是否合理

### 1.4 业务逻辑

- [ ] 实现是否符合需求描述
- [ ] 业务规则是否正确映射（状态机、流程控制）
- [ ] 数据一致性是否保证（最终一致性、补偿机制）
- [ ] 幂等性是否保证（重试、消息消费）
- [ ] 金额/数量计算精度是否满足要求

## 二、安全性检查清单

### 2.1 输入校验

- [ ] 所有外部输入是否校验（Controller 入参、MQ 消息、文件上传）
- [ ] 参数类型、长度、范围、格式是否限制
- [ ] 文件上传是否校验类型和大小
- [ ] 路径参数是否防止目录遍历（`../`）
- [ ] 反序列化是否防止反序列化漏洞

### 2.2 注入防护

- [ ] SQL 是否使用参数化查询（禁止字符串拼接 SQL）
- [ ] HQL/JPQL 是否防止注入
- [ ] XSS 是否过滤用户输入中的 HTML/JS
- [ ] 命令注入是否防护（Runtime.exec 使用场景）
- [ ] LDAP/XML 注入是否防护
- [ ] 模板注入（SSTI）是否防护

### 2.3 认证与授权

- [ ] 接口是否有认证保护（JWT/Session/Token）
- [ ] 敏感操作是否有权限校验
- [ ] 数据访问是否有越权防护（水平越权、垂直越权）
- [ ] 密码是否使用安全哈希（BCrypt/SCrypt）
- [ ] Session/Token 是否有过期机制

### 2.4 敏感数据

- [ ] 密码/密钥是否硬编码在代码中
- [ ] 日志是否脱敏（手机号、身份证、银行卡、密码）
- [ ] API 响应是否过滤敏感字段
- [ ] 配置文件中的密钥是否使用环境变量/密钥管理
- [ ] 传输是否使用 HTTPS/TLS

## 三、性能检查清单

### 3.1 数据库

- [ ] 查询条件字段是否有索引
- [ ] 是否存在 N+1 查询问题
- [ ] 批量操作是否分批执行（避免一次性加载大量数据）
- [ ] 是否存在全表扫描风险
- [ ] JOIN 是否必要，是否可以拆分为多次查询
- [ ] 索引是否被正确使用（避免函数操作索引列、避免隐式类型转换）
- [ ] 分页查询是否使用合理的分页方式

### 3.2 缓存

- [ ] 热点数据是否使用缓存
- [ ] 缓存 key 设计是否合理（避免冲突、避免过长）
- [ ] 缓存过期时间是否合理
- [ ] 是否防止缓存穿透（空值缓存、布隆过滤器）
- [ ] 是否防止缓存击穿（互斥锁、逻辑过期）
- [ ] 是否防止缓存雪崩（随机过期时间、多级缓存）
- [ ] 缓存与数据库一致性如何保证

### 3.3 代码层面

- [ ] 循环内是否有不必要的重复计算
- [ ] 字符串拼接是否在循环内使用 `+`（应用 StringBuilder）
- [ ] 集合初始化是否指定合理容量
- [ ] 是否避免不必要的对象创建
- [ ] 大集合操作是否使用 Stream（注意 parallelStream 的线程池）
- [ ] 正则表达式是否预编译（避免循环内 `Pattern.compile`）

### 3.4 资源管理

- [ ] 数据库连接是否正确释放
- [ ] IO 流是否关闭（推荐 try-with-resources）
- [ ] HTTP 连接是否设置超时
- [ ] 线程池是否合理配置（核心线程数、最大线程数、队列）
- [ ] 是否存在内存泄漏风险（静态集合、未清理的 ThreadLocal）

## 四、可维护性检查清单

### 4.1 命名与可读性

- [ ] 变量名是否表达"是什么"
- [ ] 方法名是否表达"做什么"
- [ ] 布尔变量/方法是否表达"真假含义"
- [ ] 是否避免无意义缩写
- [ ] 命名是否一致（同一概念不混用名称）

### 4.2 函数设计

- [ ] 方法是否过长（> 50 行考虑拆分）
- [ ] 参数是否过多（> 5 个考虑封装为对象）
- [ ] 方法是否职责单一
- [ ] 是否有副作用（方法名暗示的行为之外还有隐藏行为）
- [ ] 是否遵循命令-查询分离

### 4.3 代码结构

- [ ] 是否遵循单一职责原则
- [ ] 是否有重复代码可以提取
- [ ] 是否有过深的嵌套（> 3 层考虑重构）
- [ ] 是否有过大的类（> 500 行考虑拆分）
- [ ] 依赖是否合理（避免循环依赖、避免不必要的依赖）
- [ ] 是否使用魔法数字/字符串

### 4.4 测试

- [ ] 核心业务逻辑是否有单元测试
- [ ] 测试是否覆盖正常路径和异常路径
- [ ] 测试是否独立、可重复执行
- [ ] 测试命名是否清晰表达测试意图
- [ ] Mock 使用是否合理（不过度 Mock）

---

## 五、规范性检查清单

### 5.1 编码规范

- [ ] 是否遵循项目编码规范（命名、格式、注释）
- [ ] 代码格式是否统一（缩进、换行、空格）
- [ ] 注释是否说明"为什么"而非"做什么"
- [ ] 是否有过时代码/注释需要清理
- [ ] 是否有 TODO/FIXME 需要跟进

### 5.2 Git 规范

- [ ] 提交信息是否清晰描述变更内容
- [ ] 提交粒度是否合理（一个提交做一件事）
- [ ] 分支命名是否规范
- [ ] 变更范围是否合理（不应混入无关改动）

### 5.3 文档与配置

- [ ] 接口变更是否更新 API 文档
- [ ] 配置变更是否更新配置说明
- [ ] 破坏性变更是否在 PR 描述中明确说明
- [ ] 数据库变更是否有对应的迁移脚本
